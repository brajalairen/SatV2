question in plain language, get an answer with visual evidence, a confidence value with its method, a full execution
trace and downloadable reports.

| D-026 | The **change map compares both dates on one shared scale**. Old bi-temporal numbers are void. |

**Changed in the same session** (all committed): press-drag-release rectangle/circle drawing anchored at the press
point; circles and polygons analysed as the real shape rather than their bounding box; coverage figures counting only
valid pixels; one model load/generation at a time; uploads keeping the user's filename in the trace; truthful
area-failure reasons; a portable JSON report; cancel and timeout for a running analysis; a streamed, size-capped
upload; a SAR unit inference that no longer trips on a single negative sample.

**The one mandatory SIH item still missing is R5**, the remote-sensing adaptation. Nothing has been trained. No claim
about fine-tuning may be made until the run, its data and its results are in the repository (CLAUDE.md §7).

## 3. Setting up on the RTX 4050 laptop

```powershell
git clone <repo> satquery && cd satquery
uv venv --python 3.12 .venv
uv pip install --python .venv -e ".[server,ui,models,dev]"   # torch 2.8 cu128, transformers 4.49
cd web; npm ci; npm run build; cd ..
```

Then check it works before touching any GPU work:

```powershell
.venv\Scripts\python -m pytest                  # expect 110 passed
cd web; npm test; cd ..                         # expect 25 passed
$env:SATQUERY_VLM_BACKEND="falcon"; $env:SATQUERY_DEVICE="cuda"
.venv\Scripts\python -m uvicorn satquery.server:app --port 8000
```

Open <http://127.0.0.1:8000>, run **Help → a demo scenario**, and confirm the answer card and the Details trace appear.

**Windows notes.** Turn **Developer Mode on** first, or `huggingface_hub` fails with `WinError 1314` when linking cache
blobs (D-021). If Windows blocks the virtual environment's `python.exe` or a package DLL under an application-control
policy, do **not** weaken the policy: use WSL for the Python side, as the previous session did (§6).

## 4. Exact next steps for the GPU work

The reasoning, VRAM budget, dataset shape and risks are in **`docs/adaptation-plan.md`**. The order of work is §10
there. Concretely:

### Step 1 — the VRAM spike (~30 min, do this before anything else)

Write a throwaway script under `experiments/adaptation/` that:

1. loads `mehmetbayik/Falcon-Single-Instruction-Large` in fp16 on `cuda` exactly as `satquery/specialists/falcon.py`
   does (including the `flash_attn` import patch);
2. prints the model's module names — this confirms or refutes the Florence-2 assumption and tells you which modules
   LoRA should target;
3. attaches LoRA (`r=8`, `alpha=16`, decoder attention q/k/v/o, vision tower frozen) with `peft`;
4. runs **one** forward+backward on a single sample and prints `torch.cuda.max_memory_reserved() / 1e9`.

**The decision rule:** peak under ~5.2 GB → train on the 4050. Above it → move to Colab (free T4, 16 GB) and upload
only the ~700 MB subset. Record the number either way; it belongs in the write-up.

If PEFT will not attach to Falcon's `trust_remote_code` model, stop and switch to the fallback in
`docs/adaptation-plan.md` §13 (train our own BigEarthNet classifier, ~1 h, cannot fail for architectural reasons).

### Step 2 — build the training subset

`scripts/build_round1_subset.py` already does this; it needs the BigEarthNet root and the BigEarthNet.txt parquet.
**Confirm first whether the ~110 GB dataset is on this laptop or another one** (D-019 says "a team laptop"). If it is
elsewhere, run this there and copy only the resulting folder (~700 MB).

```powershell
.venv\Scripts\python scripts/build_round1_subset.py `
    --bigearthnet-root <path-to-BigEarthNet> `
    --text-parquet <path-to>/BigEarthNet.txt.parquet `
    --split train --per-class 200 --out data/adaptation/train
# repeat with --split test --per-class 50 --out data/adaptation/test
```

Then flatten the per-patch `text.json` rows into a JSONL of `{image_path, question, answer, category, split}`, render
each patch to RGB with the **same** stretch the app uses (`satquery.imaging.stretch`), and balance the yes/no rows.
`data/` is gitignored: commit the manifest, never the imagery.

### Step 3 — baseline, train, evaluate

1. Evaluate the **unmodified** model on the held-out rows first, or there is nothing to compare against.
2. Train: batch 1, gradient accumulation 8–16, lr 1e-4, 1 epoch first. Check the loss actually falls on a 20-sample
   overfit test before starting the full run.
3. Re-evaluate. Report exact-match **per `category`**, plus the yes/no base rate so "always answers yes" is visible.
4. Re-run the 8 demo scenarios and confirm nothing regressed qualitatively.

### Step 4 — wire it in

Add `SATQUERY_FALCON_ADAPTER` to `satquery/settings.py`, apply the adapter in `FalconVLM.load()`, and set `model_id`
to `"<base> + <adapter>"` so **every execution trace names the adapted model**. Nothing else changes: registry, tool
signatures, `analyze()` and the UI stay as they are.

### Step 5 — evidence

Commit the training script, config, data manifest, loss log and before/after evaluation into
`experiments/adaptation/`. **Do not commit the adapter weights** (CLAUDE.md §11): push them to the HF Hub, or keep
them on the laptop and record the SHA-256 in the write-up.

## 6. Notes a fresh session needs

- **The default model backend is `fake`.** `SATQUERY_VLM_BACKEND=falcon` is required for any real answer, and the UI
  shows an amber "Demo model" pill whenever the fake one is active. Never present fake output as a model result.
- **Old bi-temporal numbers are void** (D-026). Do not copy figures out of older drafts; measure them.
- **The main Windows machine used in the previous session has Smart App Control enabled**, which blocked the project's
  virtual-environment launcher and rasterio's DLL. The workaround was to run the Python side in WSL Ubuntu. Keep the
  policy enabled; do not attempt to bypass it. This does not affect the GPU laptop unless the same policy is on.
- **Python tests must run against the working tree**, not an installed copy: `python -m pytest` from the repository
  root.
- `docs/decisions.md` is the source of truth for decisions. Do not silently re-decide anything recorded there.
